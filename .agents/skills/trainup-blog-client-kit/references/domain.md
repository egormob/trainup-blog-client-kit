# Собственный домен

Предлагай этот шаг только после успешной публикации на техническом адресе.

1. Спроси желаемое имя домена и проверь доступность у нескольких надёжных
   регистраторов. Покажи цену регистрации и продления; уже работающий технический
   адрес Яндекса всегда оставляй альтернативой.
2. Не покупай домен и не соглашайся с платной услугой без явного подтверждения.
3. Если регистрация недоступна из Yandex Cloud или диалога Codex, дай владельцу
   одно простое действие на сайте выбранного регистратора. Вход, MFA и оплату он
   выполняет сам.
4. Проверь актуальный порядок в [официальной инструкции Yandex Cloud](https://yandex.cloud/en/docs/storage/operations/hosting/own-domain).
   Для собственного домена нужен отдельный бакет, имя которого точно совпадает с
   доменом. Нельзя просто переименовать первый технический бакет. Создай новый
   публичный бакет только после подтверждения, включи в нём статический сайт и
   оставь технический бакет рабочим как безопасную копию.
5. После регистрации сам подготовь точные DNS-записи. Для корневого домена в
   Yandex Cloud DNS используй ANAME на `ДОМЕН.website.yandexcloud.net`; для
   поддомена у стороннего DNS обычно подходит CNAME. Проверь правила выбранного
   регистратора и не меняй серверы имён без отдельного объяснения последствий.
6. Выпусти сертификат Let's Encrypt в Certificate Manager либо подключи уже
   имеющийся сертификат, затем свяжи его с новым бакетом. Certificate Manager
   может быть бесплатным, но Cloud DNS и регистрация домена могут тарифицироваться;
   каждый платный шаг подтверждается отдельно. Запрашивай дополнительные
   облачные права только на этом этапе и только минимально необходимые.
7. Обнови `baseUrl`, пересобери canonical и все GEO-файлы, покажи план публикации
   в новый бакет, опубликуй после подтверждения и проверь HTTPS. Применение
   сертификата может занять время, поэтому не объявляй успех до реальной проверки.

Не отключай рабочий технический адрес, пока собственный домен и сертификат не
прошли проверку.
