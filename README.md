# TrainUp Blog Client Kit

Готовый набор для выпуска адаптивных статей через Codex в Yandex Cloud. Внутри —
три оформленных шаблона, безопасные UTM-замены, GEO-находимость, история версий и
публикация напрямую с компьютера. Исходные статьи TrainUp в работу кита не входят
и не изменяются.

## Самый короткий старт

Передайте Codex ссылку на этот репозиторий и напишите:

```text
Установи и настрой мой блог по инструкции из https://github.com/egormob/trainup-blog-client-kit
```

Для этой задачи рекомендуется Codex на модели Sol с уровнем рассуждений Medium
или выше. Агент скачает публичный кит без входа в GitHub и будет давать по одному
понятному действию за раз.

В начале агент спросит:

> Где хранить исходники и историю блога?
>
> а) Только на этом компьютере — проще, быстрее и экономнее по токенам (рекомендуется).
>
> б) Локально на компе + Гитхаб — удалённая копия и совместная работа; потребуется дополнительный аккаунт и более длинная настройка. Выбирайте, если точно понимаете, зачем это нужно.

Новичку подходит первый вариант. Второй оставлен для людей, которым уже нужна
совместная работа или отдельная удалённая копия. Подробной настройки GitHub в
ките нет: при выборе этого варианта Codex проверит своё подключение и предложит
подключить управление, если его ещё нет.

## Что произойдёт дальше

Codex поможет создать отдельную папку блога, выбрать подходящий хостинг, собрать
первую статью из любого читаемого документа, заменить реквизиты, настроить UTM и
GEO и согласия, проверить результат и подготовить публикацию. Если вы выбрали Yandex Cloud,
агент настроит новый статический хостинг и сначала проверит технический домен Яндекса. Затем
он предложит подключить собственный домен. Для работающего сайта сохраняется его хостинг.

Пароли, ключи, токены и коды подтверждения нельзя отправлять в чат. Когда они
понадобятся, Codex откроет безопасный ввод в терминале и объяснит одно действие.
Подключение оплаты, облачные ресурсы и регистрация домена могут стоить денег;
агент обязан предупредить о цене и дождаться согласия перед платным шагом.

## Состав

- `kit/templates/basic` — «Базовый шаблон»;
- `kit/templates/advanced` — «Продвинутый»;
- `kit/templates/consent` — лендинг с согласиями;
- `kit/consent` — переносимый компонент и контрольные суммы;
- `blog` — статьи, настройки и материалы владельца;
- `output` — готовая сборка;
- `.blog-state` — локальные резервные копии и состояние публикации;
- `.agents/skills/trainup-blog-client-kit` — инструкция для Codex.

Кит не проверяет обновления и ничего не отправляет в GitHub в фоне.

## Новая система согласий

[Полная инструкция, совпадающая с PDF](docs/guide.md) включает два маршрута: «Создать новый лендинг с согласиями» и «Добавить согласия на существующий лендинг». Назовите агенту нужный заголовок — он прочитает этот раздел и инструкции внутри комплекта.

`kit/templates/consent` — третий дизайн, `kit/consent` — проверенный компонент 1.2.0. Новые проекты получают согласия по умолчанию. Выбор сохраняется до 180 дней, Метрика запускается после разрешения, а внешние ссылки сохраняют исходную вкладку для очереди. Режим counterId=0 работает без аналитики. БД, YDB и облачный сервер для согласий не требуются. Отзыв останавливает дальнейший сбор; удаление ранее переданного выполняется по процедуре оператора. Полные сведения и ограничения приведены в инструкции.
