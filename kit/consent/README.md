# Локальный шаблон согласий — 1.2.0

Клиентская поставка: компонент применяется по умолчанию при создании нового лендинга.
Генератор: `node scripts/consent-kit.mjs` (из корня клиентского комплекта). Python не нужен. Для сборки не нужны Git, сеть или исходный рабочий лендинг.

## Настройки

Возьмите `kit/consent/settings.example.json`. Задайте свои реквизиты, контакты, URL документов, версию согласия, счётчик и цели. `counterId=0` означает отсутствие аналитики. `newsletterEnabled` включает текст и ссылки о рассылке только при её фактическом наличии. `serviceIdsEnabled` включает пояснение ID Telegram/ВК только для соответствующей услуги. Чужой счётчик, сервер атрибуции и пользовательские идентификаторы не переносятся.

## Новый лендинг

```sh
node scripts/consent-kit.mjs build --settings config/new-project.json --output sites/new-project
```

Создаётся адаптивная страница с подстановками, галочкой, панелью, юридическими ссылками и колонтитулом. Изображения — стартовый пример: замените их под предложение. У проекта собственные заголовок, описание, канонический URL и цели. Черновик остаётся noindex до штатной приёмки.

## Свой дизайн, SEO и замены заголовков

Сохраните свою структуру, head/SEO/GEO и разрешённые замены текста. Над основной CTA поставьте `<!-- LANDING_CONSENT -->`, в колонтитуле — `<!-- LANDING_LEGAL_FOOTER -->`. Для защищаемых ссылок/кнопок добавьте `data-consent-cta="имя-действия"`; для мессенджеров поддерживается прежний `data-channel`. Внешние CTA — нативные ссылки с `target="_blank" rel="noopener"`.

```sh
node scripts/consent-kit.mjs build --settings config/new-project.json --page workspace/new-design.html --output sites/new-project
```

Компонент и колонтитул вставляются автоматически; остальные байты HTML сохраняются. Маркер согласия ставьте в том же контейнере ширины, что и основная CTA: блок занимает его ширину и выравнивается с кнопкой. Маркеры ставьте вне form/label. Счётчик отдельным скриптом не запускайте. Генератор отказывает при пропущенном или повторном маркере, отсутствии CTA, дублировании согласия либо отдельном известном SDK аналитики.

Для другого builder/GetCourse используйте `--component-only`: он выдаёт `consent-component.html` (div, inline CSS/JS) и `legal-footer.html`. Builder вставляет их через те же маркеры после персонализации и SEO. Скрипт ждёт DOMContentLoaded для привязки CTA; ранний обработчик блокирует действия до готовности UI. Проверьте ширину блока и выравнивание с кнопками. Сборщики платформы и её формы проверяются отдельно: компонент не управляет чужими SDK автоматически.

## Сохранённое поведение

Пустое согласие блокирует CTA, показывает подсказку над галочкой и встряхивает кнопку. «Настроить» открывает черновик: все пункты изначально отмечены, обязательные недоступны для отключения. Только «Сохранить выбор» применяет ограничения. Частичный выбор показывает черточку; клик по ней или «Принять все» возвращает полный выбор. Отказ от аналитики через панель позволяет продолжить без счётчика. Снятие основной галочки снова блокирует CTA. Выбор сохраняется до 180 дней, с отдельным ключом проекта и версией; истечение и повреждённое значение не становятся согласием.

Метрика и Вебвизор запускаются только при соответствующем разрешении; цель передаётся на разрешённый клик. Нативный переход не ждёт SDK, сервер или таймер. Отзыв прекращает дальнейший сбор и чистит доступное хранилище этого сайта. Удаление ранее отправленного Яндексу выполняется по процедуре оператора.

Яндекс Cloud/YDB не нужны. Серверная доставка и журнал, другие пиксели, фактическая подписка на рассылку и обработка контактов не появляются автоматически. Браузерная схема не гарантирует передачу без сети, при блокировщике, закрытии всех вкладок или остановке браузера ОС.

## Проверка перед публикацией

Проверьте подстановки, действующие документы и все фактические сборщики: отсутствие запросов аналитики до выбора, пусто/галочка/черточка, сохранение/отзыв/срок, документные ссылки без установки галочки, мгновенный переход с холодным SDK и регистрацию своей цели. Проверьте мобильный/планшет/десктоп, выравнивание, фиксированные заголовок и кнопки панели, прокрутку и отсутствие переполнения.

Генерация ничего не публикует и отказывается перезаписывать существующий каталог. Документы исходного оператора не универсальны: у копии явно задаются свои юридические URL. Источник принятого интерфейса: `iik-ai-marketer-consent-release-v1.1.3`. Подробный контракт: `docs/guide.md` и `.agents/skills/trainup-blog-client-kit/references/consent-installation.md`.

В клиентской поставке фотопортреты автора в иконках заменены нейтральным SVG. Runtime guard.js, cookie-consent.js и consent-analytics.js версии 1.2.0 сохранён побайтно. Свои иконки клиент добавляет отдельно под свой бренд.
